AGENTS.md — VYAPAAR project context

What this project is
VYAPAAR — a real full-stack application (not a demo/college project) that digitizes a wholesale garlic trading business: customers, suppliers, products, purchases, sales, payments, and udhari (credit) tracking. It will be used daily by a non-technical business owner. Correctness of money calculations matters more than speed of delivery.
Non-negotiable rules
Do not change the project architecture once a module is built. No "better approach" refactors mid-project.
Do not introduce enterprise patterns, extra abstraction layers, or design patterns not already in use. Keep classes small and simple.
Balances (customer/supplier) are NEVER stored as a mutable field. They are always computed fresh from sales/purchases/payments via `LedgerService`. If you ever find yourself about to add a `balance` column, stop — that violates the core design.
Package structure stays: `entity`, `repository`, `service`, `controller`, `config`, `exception`, `util`. Don't add new top-level packages without asking.
Complete and test one module fully (entity → repository → service → controller → manually verified via Postman or a quick curl) before starting the next. Do not build multiple modules in parallel.
After finishing each module: run the app, confirm it compiles and the relevant endpoint actually returns correct data, THEN report back to the user with what was built and how to verify it — do not silently continue to the next module in the same turn.
Never commit real secrets. DB password is `${DB\_PASSWORD}` env var, already fixed — do not reintroduce a hardcoded password.
Tech stack (fixed — do not deviate)
Backend: Java 21, Spring Boot, Spring Data JPA, MySQL, Maven, Hibernate
Frontend: React (Vite, TypeScript), Tailwind CSS v4 (theme via `@theme` in `src/styles/index.css`, not `tailwind.config.js`), react-i18next for Hindi/English
Testing: Postman for backend endpoints
Package base: `com.vyapaar`
